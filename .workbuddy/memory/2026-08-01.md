## 修复:集合分页刷新按钮导致左侧数据库树收起

- **现象**:点击 DocTable 顶部"刷新数据"按钮后,左侧 DbTree 已展开的数据库集合列表消失,视觉上像"展开被收起来",再点反而折叠。
- **根因**:DocTable 刷新按钮 `onClick={() => { triggerReload(); doRefresh(); }}` 同时触发两个信号。`doRefresh()` → `refreshKey+1` → DbTree 的 `useEffect` 执行 `setCollections({})` 清空所有集合缓存;但 `expandedDbs` 仍为 true → 展开区域渲染空列表,状态错乱。
- **修复**:
  1. `DocTable.jsx`:刷新按钮去掉 `doRefresh()`,只保留 `triggerReload()`(重新拉取当前集合文档),从解构中移除 `doRefresh`。
  2. `DbTree.jsx`:refreshKey 副作用改为"清空集合缓存 + 保持已展开库的展开状态并自动重新加载其集合列表";用 `expandedDbsRef`(useRef 同步)读取最新展开状态,`refreshKey===0` 跳过首次挂载。
- **结论**:"刷新文档数据"与"刷新左侧集合缓存"是两件事,不该耦合。后续新增任何触发 doRefresh 的地方,DbTree 均会保持展开并重载,不会出现空白态。

## Bug 修复:新建集合弹窗不关闭导致界面卡住(已完成)

- **现象**:点击"创建集合"按钮,集合在 MongoDB 中成功创建,但弹窗不关闭,整个界面被 mask 挡住无法点击
- **根因**:`DbTree.handleCreate` 是 antd Modal 的 onOk,内部 await `createCollection` → message.success → **await `listCollections`** → ... → 最后才 `setCreateModal({open:false})`。一旦 `listCollections` 挂起/报错,关闭弹窗的 setState 永远走不到;同时 antd Modal 在 onOk 返回 Promise 时按钮进入 loading,遮罩 mask 挡住整个应用,造成"弹窗没关 + 无法点击"
- **修复**:`createCollection` 成功后**立即**关闭弹窗、清输入,Promise 快速 resolve;把 `listCollections` / `setSelectedDb` / `setSelectedCollection` 等收尾操作抽到独立的 `refreshAfterCreate(isNewDb, dbName, colName)`,在 handleCreate 主流程之外异步执行(失败静默,用户可手动刷新)
- **创建失败**:`createCollection` 抛错时 catch 内 message.error 并 return,弹窗保持打开便于用户修改重试
- **构建验证**:vite build 通过;复现因环境复杂(ELECTRON_RUN_AS_NODE、共享 vite、端口冲突)未实际跑通,改动逻辑清晰,需用户在原应用验证
- **ShellPanel 手动执行不拦截**(requireConfirm 默认 false)
- 正则验证:19 用例全过(正常查询/insertOne/updateOne/deleteOne/dropIndex/字符串含"drop"均不误伤;批量/破坏性全拦截),vite build 通过
